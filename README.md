# ReflectPulse 🔮

ReflectPulse is a private AI journaling app built with Streamlit. It lets a user hold a multi-turn conversation with Gemini, save structured reflection data to Firestore under that user’s identity, and review mood, theme, streak, and weekly digest information.

## Features

- Google OAuth 2.0 sign-in using an authorization-code flow and Google ID token verification.
- Multi-turn Gemini chat sessions using `gemini-3.6-flash`.
- Voice note capture for `.wav`, `.mp3`, and `.m4a` files.
- Photo capture for `.jpg`, `.jpeg`, and `.png` files.
- Structured reflection analysis using the Pydantic `ReflectionResponse` model in `gemini_service.py`, including a summary, mood category, mood score, theme tags, reflection prompt, location tag, and optional perspective note.
- Firestore journal persistence scoped to the authenticated user.
- Plotly mood trajectory and theme distribution charts generated by `analytics.py`.
- Current and maximum consecutive-day streak calculations.
- A Gemini-generated weekly reflective digest based on the entries passed to the digest function.
- A separate Perspective Shift action that generates a short, non-clinical alternative perspective for a difficult thought.
- A Streamlit interface with two selectable color themes: Warm Charcoal and Obsidian Flame.

## Architecture

The browser connects to the Streamlit application in `app.py`. Unauthenticated users are sent through the OAuth flow implemented in `auth.py`. After Google identity verification, `app.py` creates a Gemini chat session and uses `gemini_service.py` for chat replies, multimodal reflection analysis, Perspective Shift responses, and weekly digest generation. Journal reads and writes go through `firestore_service.py`, which addresses each user’s journal subcollection. `config.py` resolves `GEMINI_API_KEY` from Google Cloud Secret Manager first, then from an environment variable or Streamlit secrets.

```text
Browser
  |
  v
Streamlit app (app.py)
  |-- auth.py ---------------------- Google OAuth code exchange and ID token verification
  |-- gemini_service.py ------------ Gemini chat and reflection generation
  |-- firestore_service.py --------- Per-user Firestore reads and writes
  |-- analytics.py ------------------ Streaks and Plotly charts
  `-- config.py -------------------- Gemini key resolution
          |
          +--> Google Cloud Secret Manager
          +--> GEMINI_API_KEY environment variable
          `--> Streamlit secrets fallback
```

The application uses Firebase Admin SDK for server-side Firestore access. `firestore_service.py` initializes it from the file named by `FIREBASE_APPLICATION_CREDENTIALS` when that file exists, and otherwise tries Application Default Credentials.

## Project structure

| File | Description |

## Data model

Journal documents are written to the following Firestore path:

```text
users/{user_id}/journals/{entry_id}
```

`create_journal_entry()` in `firestore_service.py` creates a new document in that user’s `journals` subcollection. The document includes the fields supplied by `app.py` during synthesis:

- `title`: User-provided or generated reflection title.
- `content`: Serialized conversation text with `User:` and `AI:` labels.
- `chat_transcript`: The raw list of chat messages, each containing a role and content.
- `summary`: Structured reflection summary.
- `mood_category`: Extracted mood label.
- `mood_score`: Extracted mood score.
- `theme_tags`: Extracted theme labels.
- `reflection_prompt`: Follow-up reflection question.
- `location_tag`: Selected or inferred context.
- `perspective_note`: Optional perspective shift.
- `has_audio`: Boolean indicating whether audio was attached during save.
- `has_image`: Boolean indicating whether an image was attached during save.
- `user_id`: The user ID supplied to the CRUD function.
- `created_at`: The supplied creation time, or a UTC time generated by the service.
- `updated_at`: A UTC time generated when the document is created or updated.

The service also accepts additional keys from `entry_data` because it expands that dictionary into the document. For compatibility, it can read `cognitive_reframe` when constructing `perspective_note`, and it can map legacy data containing `cognitive_reframe` when reading entries.

## Firestore security rules

These rules allow an authenticated user to read, write, or delete documents only under their own `users/{userId}/journals/{journalId}` path, where `userId` must match `request.auth.uid`. Deploy these rules to the Firebase project alongside the app so isolation is enforced server-side, not only in application code: `firebase deploy --only firestore:rules`.

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Multi-tenant isolation: Users can only read/write their own journals
    match /users/{userId}/journals/{journalId} {
      allow read, write, delete: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

## Setup and running locally

### Prerequisites

- Python 3.11 or newer.
- A Firebase project with Firestore enabled.
- A Gemini API key.
- A Google OAuth 2.0 client with a redirect URI for the local app.
- Firebase credentials available either through a service-account file or Application Default Credentials.

### 1. Create a virtual environment

Windows PowerShell:

```powershell
python -m venv venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\venv\Scripts\Activate.ps1
```

macOS or Linux:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment variables

Create a `.env` file in the project directory for local development. `config.py` and `auth.py` read these variables:

```dotenv
GCP_PROJECT=your-google-cloud-project-id
GEMINI_API_KEY=your-gemini-api-key
FIREBASE_APPLICATION_CREDENTIALS=C:\path\to\service-account.json
GOOGLE_CLIENT_ID=your-oauth-client-id
GOOGLE_CLIENT_SECRET=your-oauth-client-secret
REDIRECT_URI=http://localhost:8501
```

`config.py` defaults `GCP_PROJECT` to `rakshith-0408` when it is not set. It always uses the secret name `GEMINI_API_KEY` and version `latest`. It attempts Secret Manager first, then `GEMINI_API_KEY`, then `st.secrets["GEMINI_API_KEY"]`.

`auth.py` defaults `REDIRECT_URI` to `http://localhost:8501` when it is not set. Add the same URI to the Google OAuth client configuration. The OAuth request uses the `openid email profile` scopes.

`firestore_service.py` uses `FIREBASE_APPLICATION_CREDENTIALS` only when it points to an existing file. Otherwise, it calls Firebase Admin initialization without explicit credentials and relies on Application Default Credentials.

### Configuration reference

`firestore.rules` is included in the repository root. Deploy it with the Firebase CLI or through the Firebase Console before first use.

### 4. Run the application

```bash
streamlit run app.py
```

Open `http://localhost:8501` in a browser. The application first initializes Firebase Admin and stops with a connection message if a Firestore client cannot be created. After sign-in, the journal and analytics views become available.

## Deployment

The `Dockerfile` uses `python:3.11-slim`, installs the packages in `requirements.txt`, copies the project into `/app`, exposes port `8080`, and starts Streamlit with:

```text
streamlit run app.py --server.port=8080 --server.address=0.0.0.0 --server.enableCORS=false
```

It sets `PORT=8080` and defines a container health check against Streamlit’s `/_stcore/health` endpoint. Build the image with Docker and deploy that image to a Cloud Run service configured to send traffic to port 8080.

Example commands using Google Cloud Build and Cloud Run:

```bash
gcloud builds submit --tag gcr.io/PROJECT_ID/reflectpulse
```

```bash
gcloud run deploy reflectpulse \
  --image gcr.io/PROJECT_ID/reflectpulse \
  --platform managed \
  --region REGION \
  --port 8080 \
  --allow-unauthenticated
```

For a deployed environment, provide Google Application Default Credentials or an attached runtime identity that can access Secret Manager and Firestore. Set `GCP_PROJECT` and `REDIRECT_URI` for that environment, and add the deployed HTTPS redirect URI to the Google OAuth client configuration.

## Security notes

- The Gemini key is not defined in the Python source. `config.py` first attempts Google Cloud Secret Manager and falls back to an environment variable or Streamlit secrets.
- `verify_tenant_context()` in `firestore_service.py` rejects missing or empty user IDs before CRUD operations run.
- Journal reads and writes use `users/{user_id}/journals/{entry_id}`. Specific reads, updates, and deletes also compare the stored document’s `user_id` with the requested user ID.
- Google OAuth credentials are exchanged and ID tokens are verified in `auth.py`; the application does not implement its own password storage.
- The Gemini system instruction describes privacy boundaries, a reflective-companion boundary, gentle perspective shifts, crisis redirection, and concise responses. This is prompt guidance, not a replacement for application or human safety review.
- ReflectPulse is not a substitute for professional mental health care or emergency support. The UI states that it is for personal insight, not medical or mental health advice.

## Known limitations

- Uploaded audio and image bytes are sent to Gemini during reflection synthesis but are not stored in Firestore. The saved document contains only `has_audio` and `has_image` flags.
- The weekly digest function does not query Firestore or filter dates itself. `app.py` passes `entries[:10]`, which are the ten most recently loaded entries, to `generate_weekly_digest()`.
- `requirements.txt` lists package names without version pins, so dependency resolution can change between environments.
- The application uses Firebase Admin SDK server-side access. The browser OAuth flow verifies Google identity but does not create a Firebase Web SDK authentication session.
- The configured fallback model list currently contains the same model as the primary model: `gemini-3.6-flash`.
- If the Gemini client is unavailable, structured analysis returns a local fallback response, but live chat and digest generation cannot use Gemini.
- `update_journal_entry()` and `delete_journal_entry()` exist in `firestore_service.py`, but the current UI exposes loading and deletion from the history rail rather than an entry-edit workflow.
- The uploaders restrict accepted extensions, but the application does not define an explicit byte-size quota for uploaded media.
